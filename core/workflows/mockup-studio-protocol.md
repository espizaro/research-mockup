# Mockup studio protocol

- Start with domain, concept and outcomes: read the module docs/code and research the web
  (job to be done, competitors, best practices, must-have vs nice-to-have) before Mobbin;
  save a `concept-brief.md` when the objective is not explicit.
- Build navigable HTML/CSS mockups with the product's real tokens: no server, no fetch,
  works with double-click.
- Shared engine: tokens.css (exact copy), base.css (semantic tokens only),
  icons.js/illustrations.js (embedded), app.js (screens/sheets/steps).
- Design rules: sentence case, max 3-4 type styles, no borders/shadows on cards, M3 motion,
  one primary CTA, never 100vh.
- Cover states: happy path, empty, new user, success, error, light/dark.
- Verify before delivery: headless check (0 broken images, icons injected, no console
  errors), screenshots light/dark, vision review (modlens).
- Register every mockup in the hub so it appears in the studio index.
